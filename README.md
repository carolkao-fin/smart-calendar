# 排程曆

輸入「什麼時候要完成」和「需要多久」，自動排進未來的工作日。
單檔純前端，沒有後端也沒有帳號，資料只存在你自己的瀏覽器裡。

**線上版**

- GitHub Pages — <https://carolkao-fin.github.io/smart-calendar/>
- Streamlit Cloud — 見下方「部署」

---

## 使用

用瀏覽器打開 `index.html` 就能用，資料存在瀏覽器本機（localStorage），不會上傳。

**排程規則**

每天從所有未完成的任務裡，挑「密度」最高的先做：

```
密度 = 剩餘時數 ÷ 到期前還剩幾個工作天
```

越接近截止、剩越多的，密度越高，就越早被排進來。排完一天的可用時數就換下一天，
遇到週末、休假日、非工作日直接跳過。

**每天每件事都會往前走一點**

預設的「平均分攤」會先讓當天每件能做的事各拿到 0.5 小時，剩下的容量再照密度分。
所以同一天通常會排進好幾件事，而不是最急的那件把一天吃光、其他事乾等到下週。

保底只會用掉當天一半的容量，另一半仍留給最急的事 —— 否則為了雨露均霑，
真正該交的東西會遲交。想回到「一件一件做完」，把排程策略改成「儘早做完」。

**四種事情，一份清單**

| 你輸入 | 變成什麼 |
|---|---|
| 日期 + 時數 | 一般任務，自動拆塊排進工作日 |
| 日期 + **時間** + 時數 | 固定時段（開會、看診），不會被拆開，也會吃掉當天容量 |
| 只有時數，**不填日期** | 無期限，撿別人用剩的容量做，永遠不會被標成「會遲交」 |
| 連時數都不填 | 純清單項目，不佔行事曆，只是記一筆待辦 |

**清單先講今天**

任務清單分成四段，順序就是你該關心的順序：

| 分段 | 放什麼 |
|---|---|
| 今天 | 今天到期（含已經過期的），或今天有排到工作的事 |
| 接下來 | 之後才到期的 |
| 無期限・清單 | 沒有截止日的，有空再做 |
| 已完成 | 做完的，收在最下面 |

任務左邊都有勾選框，打勾就劃掉。

**誤按完成可以恢復**

勾錯了不用重建任務：已完成的任務上有「恢復」鍵，再按一次勾選框也可以。
恢復是**還原成勾選前的樣子** —— 原本做到一半的時數會回來，不會被歸零，
重複任務也會退回原本那一次的日期。

**重複的事情只要建一次**

新增或編輯任務時選「重複頻率」：每天、每個工作日、每週、每兩週、每月、每年。
標記完成後，這件事不會消失，而是自動排到下一次：截止日往後推、時數歸零重新算，
其他設定（時數、優先度、只在星期幾做）都留著。

- 沒填日期也能重複，這時往後推的是「最早可開始」那天
- 錯過好幾次沒關係，補完成時會直接跳到**下一個還沒到的日子**，不會補一堆過去的日期
- 日曆上之後的次數以虛線框預告；排程只計算「這一次」的時數，
  預告的那幾天不會被算進負載

**可以指定某件事只在星期幾做**

新增或編輯任務時展開「只在特定星期做」，勾選六、日，這件事就只會排在週末 ——
**這會蓋過設定裡的全域工作日**，所以平日上班、週末才做的事也排得進去。
留空就依全域設定。

**時間可以用小時、天或週輸入**

「這份報告要兩天」比「要八小時」好估。單位換算以你的設定為準：

```
1 天 = 每日可投入時數                    （預設 4h）
1 週 = 一週的工作日數 × 每日可投入時數    （預設 5 × 4 = 20h）
```

所以「2 天」是指**佔掉你兩個工作天的可投入時間**，不是連續 48 小時。
輸入時下方會即時顯示換算結果，不會猜錯。資料一律以小時存放，
日曆、進度、每日容量也都以小時計 —— 單位只是輸入時的便利。

**可以調的設定**

| 設定 | 預設 | 作用 |
|---|---|---|
| 每日可投入時數 | 4h | 一天總共排多少工作 |
| 單一任務每日上限 | 2.5h | 避免一整天被同一件事吃掉；趕不上截止日時會自動放寬 |
| 工作日 | 週一～週五 | 取消勾選就不排那天 |
| 提前完成緩衝 | 1 天 | 目標比截止日早幾天做完 |
| 排程策略 | 平均分攤 | 每天每件事都推進一點；或改「儘早做完」把最急的一件先做完 |
| 請假日 | — | 指定日期完全不排 |

**狀態標示**

- `從容` 排得進，且在緩衝日前做完
- `緊繃` 排得進，但會用掉緩衝
- `會遲交` 依現在的容量會超過截止日
- `排不進` 可用的日子已被更急的事佔滿，這些時數無處可放
- `固定` 固定時段，時間到了就做
- `已過` 固定時段的時間過了還沒標記完成
- `無期限` 沒有截止日，撿空檔做
- `清單` 沒填時數，只是記一筆待辦

日曆上每格底部的細條是當天的負載，背景越深表示排得越滿，超過容量會轉紅。

**完成紀錄**

日曆右上角切到「完成紀錄」，可以看每天實際做完了什麼：

- 上方四格：今日完成時數、本週完成時數、今日結案件數、累計結案件數
- 下方依日期由新到舊分段，每天標出當日總時數與筆數
- 每一筆都可以「恢復」，還原成那筆紀錄之前的狀態

紀錄有兩種來源：今日面板按「完成 Xh」的**打卡**，和勾選完成的**結案**。
只保留最近 600 筆，不會讓瀏覽器儲存空間無限長大。

**匯出**

「匯出」可下載 `.ics` 匯入 Google 日曆／Outlook／Apple 行事曆（每段工作從上午九點起排，
固定時段用它自己的時間），或下載 `.json` 備份全部任務與設定。

**隱私**

沒有後端、沒有帳號、沒有追蹤，也不載入任何外部字型或分析工具。
任務資料只存在你這台裝置的瀏覽器裡，不會上傳到任何地方。
換裝置或想長期保存，請用「匯出 → 下載 JSON」自行備份。

## 部署

### GitHub Pages（推薦，行事曆的正式家）

這是純前端網頁，Pages 是最合適的載體：載入快、網址固定、localStorage 正常運作。
repo 設定裡 **Settings → Pages → Source 選 `Deploy from a branch`、分支 `main`、資料夾 `/ (root)`**，
存檔後約一分鐘就會出現在
<https://carolkao-fin.github.io/smart-calendar/>。
之後每次 push 到 `main` 會自動更新。

### Streamlit Cloud

`streamlit_app.py` 把 `index.html` 原樣嵌進 Streamlit 頁面。

1. 到 <https://share.streamlit.io/> 用 GitHub 帳號登入
2. **Create app** → **Deploy a public app from GitHub**
3. Repository 選 `carolkao-fin/smart-calendar`，Branch `main`，
   Main file path 填 `streamlit_app.py`
4. **Deploy**，等相依套件裝完即可

> Streamlit 是把網頁放進 iframe 呈現。若你的瀏覽器封鎖了第三方網站資料，
> iframe 內可能無法保存 —— 真的發生時頁面上方會出現「無法存檔」的橘色提示，
> 這時請改用 GitHub Pages 的網址，或用「匯出 → 下載 JSON」自行備份。

## 檔案

```
index.html        網頁本體，單檔、無外部相依
streamlit_app.py  Streamlit Cloud 入口，只是把 index.html 嵌進去
test_browser.py   以 headless Chrome 實際跑頁面並驗證排程結果
requirements.txt  相依套件（只有 Streamlit 用得到）
開發紀錄.md       開發歷程、技術決策與踩過的坑
```

**測試**

```
python test_browser.py
```

不需要安裝套件，系統裡有 Chrome 或 Edge 即可。
它會用 headless 模式真的把 `index.html` 跑起來，
從渲染後的畫面驗證排程結果、任務分組與各種標示，
也會實際去點勾選框、打卡與恢復鍵，驗證重複任務與完成紀錄的行為。

開發過程中的技術決策、遇到的問題與解法，記錄在
[開發紀錄.md](開發紀錄.md)。
